KEY ACHIEVEMENTS
═══════════════════════════════════════════════════════════════════════════════

1. LANGUAGE INDEPENDENCE

   The behavioral IR output contains ZERO language-specific constructs:

   VHDL                          →   Behavioral IR
   ────────────────────────────────────────────────────────────
   std_logic                     →   bool
   std_logic_vector(1 downto 0)  →   BInt{width=2; signed=Unsigned}
   signal <= value               →   BAssign{lhs="signal"; rhs=...}
   process(CLK, RST)             →   BSequential{clock="CLK"; reset="RST"}
   CLK'event and CLK='1'         →   clock_edge=`Pos
   variable := value             →   BAssign{...}  (same as signal)

   This means SystemVerilog will produce THE SAME IR!

2. UNIFIED PROCESS MODEL

   Both VHDL and SystemVerilog processes map to:
   - BCombinational: sensitivity-based, no clock
   - BSequential: clock edge, optional reset, sync/async

   VHDL:  process(CLK, RST) begin ... end process
   SV:    always_ff @(posedge CLK or posedge RST) ...
          ↓
   Both → BSequential{clock="CLK"; clock_edge=`Pos; reset="RST"; ...}

3. OPTIMIZATION-READY STRUCTURE

   The IR is designed for standard compiler optimization passes:

   ✓ SSA Construction:
     - Simple assignment targets (strings)
     - Easy to rename: "iQ" → "iQ_1", "iQ_2"
     - Phi insertion at control flow joins

   ✓ Register Inference:
     - All BSequential assignments are potential registers
     - Build MUX trees from conditional assignments
     - SINGLE SHARED PASS for all languages!

   ✓ Dead Code Elimination:
     - Track variable uses
     - Remove unused BAssign statements

   ✓ Common Subexpression Elimination:
     - Hash BExpr nodes
     - Reuse common computations

   ✓ Constant Propagation:
     - Track BConst values
     - Fold at compile time

HOW THIS SOLVES THE VHDL REGISTER BUG
═══════════════════════════════════════════════════════════════════════════════

BEFORE (Current Architecture):

  VHDL AST → vhdl_to_ir.ml → opt_ir (creates 6 registers ❌)
     |
     ├─ Tries to infer registers during conversion
     ├─ Creates Register node for each assignment
     └─ Result: 6 registers for slib_clock_div

  SV AST → sv_verible_to_ir.ml → opt_ir (creates 2 registers ✅)
     |
     ├─ Groups assignments by signal
     ├─ Builds MUX trees
     └─ Result: 2 registers for slib_clock_div

  Problem: Each frontend has different register inference logic!

AFTER (New Architecture):

  VHDL AST → vhdl_to_behavioral.ml ──┐
                                     ├→ Behavioral IR
  SV AST → sv_to_behavioral.ml ──────┘
                                     ↓
              ╔═══════════════════════════════════╗
              ║  SHARED OPTIMIZATION PASSES       ║
              ║                                   ║
              ║  1. SSA construction              ║
              ║  2. Register inference ← HERE!    ║
              ║  3. CSE, DCE, constant folding    ║
              ╚═══════════════════════════════════╝
                                     ↓
                              opt_ir (dataflow)

  Solution: Register inference happens ONCE, works identically for all languages!

  Both VHDL and SV produce the same behavioral IR, so register inference
  produces the same result: 2 registers ✅

COMPARISON TO LLVM/GCC
═══════════════════════════════════════════════════════════════════════════════

This architecture follows proven compiler design patterns:

LLVM:
  C → Clang → LLVM IR → Optimization Passes → Machine Code
  C++ → Clang → LLVM IR → Optimization Passes → Machine Code
  Rust → rustc → LLVM IR → Optimization Passes → Machine Code

GCC:
  C → gcc → GIMPLE IR → Optimization Passes → RTL → Assembly
  C++ → g++ → GIMPLE IR → Optimization Passes → RTL → Assembly
  Fortran → gfortran → GIMPLE IR → Optimization Passes → RTL → Assembly

Our System:
  VHDL → vhdl_to_behavioral → Behavioral IR → Opt Passes → opt_ir → Backend
  SV → sv_to_behavioral → Behavioral IR → Opt Passes → opt_ir → Backend
  Chisel → (future) → Behavioral IR → Opt Passes → opt_ir → Backend

Key insight: Multiple frontends, ONE optimization infrastructure!
