═══════════════════════════════════════════════════════════════
CRITICAL FIX APPLIED
═══════════════════════════════════════════════════════════════

PROBLEM FOUND: VHDL frontend was creating registers for EVERY
               assignment, instead of one register per signal!

EXAMPLE:
  process (CLK, RST)
  begin
    if RST = '1' then
      iQ <= '0';         -- Assignment 1
    elsif CLK'event then
      iQ <= '0';         -- Assignment 2
      if CE = '1' then
        iQ <= '1';       -- Assignment 3
      end if;
    end if;
  end process;

BEFORE FIX: Created 3 registers for iQ (wrong!)
  - Register(iQ) 
  - Register(iQ_next1)  ← Should be wire/mux!
  - Register(iQ_next2)  ← Should be wire/mux!

AFTER FIX: Created 1 register for iQ (correct!)
  - Register(iQ) with mux tree selecting values

═══════════════════════════════════════════════════════════════
WORD-LEVEL vs BIT-BLASTING
═══════════════════════════════════════════════════════════════

WORD-LEVEL (what we did):
  iCounter (2-bit): 1 Z3 bitvector
  iCounter + 1:     1 Z3.BitVector.mk_add call
  Solver sees:      arithmetic constraint

BIT-BLASTED (what we avoided):
  iCounter (2-bit): 2 boolean variables (bit0, bit1)
  iCounter + 1:     6 boolean gates (XORs, ANDs for carry)
  Solver sees:      huge boolean formula

SPEEDUP: ~10-100x for arithmetic-heavy circuits
