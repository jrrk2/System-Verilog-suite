   Benefits:

═══════════════════════════════════════════════════════════════════════════════
THE KEY INSIGHT: SHARED REGISTER INFERENCE
═══════════════════════════════════════════════════════════════════════════════

BEFORE (Buggy Approach):

  Each language frontend tries to do register inference during IR conversion:

  vhdl_to_ir.ml:
    List.iter (fun (dst_id, data_id) ->
      let _reg_id = add_node ctx (Register { ... }) [data_id]  ← Creates register for EVERY assignment!
    ) assigns

  Result: 6 registers for slib_clock_div (4 extra!) ❌

AFTER (New Architecture):

  Language frontends just convert to behavioral IR.
  Register inference is a SHARED pass:

  behavioral_registers.ml:
    1. Groups assignments by target signal
    2. Builds priority MUX tree from conditions
    3. Creates ONE register per unique signal

  Result: 2 registers for slib_clock_div ✅

Key benefit: Bug fix applies to ALL languages automatically!

═══════════════════════════════════════════════════════════════════════════════
OPTIMIZATION PIPELINE ORDER (AND WHY)
═══════════════════════════════════════════════════════════════════════════════

1. SSA Construction FIRST
   - Normalizes variable naming
   - Makes dataflow explicit
   - Required by other passes

2. Constant Propagation SECOND
   - Uses SSA form for tracking values
   - Creates opportunities for DCE
   - Simplifies expressions for CSE

3. Dead Code Elimination THIRD
   - Removes code exposed by constant propagation
   - Cleans up before CSE
   - Reduces work for later passes

4. Common Subexpression Elimination FOURTH
   - Works on simplified expressions
   - Creates temps that need register analysis
   - Last dataflow optimization

5. Register Inference LAST
   - Needs all optimizations complete
   - Determines final hardware structure
   - Separates registers from combinational logic
